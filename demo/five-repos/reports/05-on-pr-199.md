# The stacks on the head of #199, against main, 2026-11-03

The latest pull request is #199, "reports: coming-up, agents-md-check,
xref, pins and box-health print a report", head `reports/batch-3`,
stacked on #198 and #197 above main: 50 commits, 93 files. It puts 23
add-ons on one report shape (`NAME: STATE, SAID`, then `## group` and
`where  what` rows, with `--json` the same) and changes `stack` itself: a
step whose card says `output: report` is run with `--json`, printed by
stack in that shape, its height counted in rows rather than lines, and
flagged by its exit code alone. Nine of the audit stack's steps are on

All five stacks ran on that head, read-only, with the same boxes, and
each page was compared with its main twin by step and state, the way

audit page predated the words list, so the audit stack ran on main again
with the list on the box. Willow is back on its working branch; the PR
head stays fetched and is one checkout away.

## What the PR did to the audit page

- **Pool order moved.** "What the code still owes" now stands above
  "names the rest of the world already uses". Its five report steps are
  measured in rows and the three `ids` steps still in lines, so the two
  pools are weighed in different units. That is the PR's rule as written
  (rows decide a report's mass) and worth knowing when reading a page
  that mixes report and non-report steps.
- **digest shrank from 273 lines to 137** by printing only groups with
  rows: no "Waiting for you: nothing" blocks. box-health grew from 6
  lines to 13 by becoming groups, with a `words list as last used` row.
- **The report's `what` keeps the whole thing.** install-scripts' one row
  still carries the planted `curl ... | sh` in full; pins' rows carry the
  range; the secrets rows say `value not shown`.
- **The state word.** why-not prints `empty` for "where is the vault" and
  then says the files do hold it. Its card's rule is that a held
  question is empty, which reads oddly on a page where empty otherwise
  means nothing found.

## The confound, and the fix

The first comparison showed first-mention of "vault" jumping from 129
mentions in 24 files to 12,286 in 1,008, first seen in 1900. That was not
the PR. The PR run's box carried the pruned words list, so vault read as
record, ledger, chain and the rest, and the main page had been made
before the list existed. main rerun with the list gives 12,176 in 1,006
files and the same 1900 date, and the PR's two extra files are the whole
difference. A comparison is only by step and state when the boxes match
too, so the rebuild script's words list now counts as part of the box.
