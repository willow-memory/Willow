`gh-json` 0.2.0 reads GitHub's REST API answers as well as gh's `--json`: its own names (`user`, `created_at`, `head.ref`, `merged_at`, `draft`, a run's `id` and `head_branch`) and a list wrapped in an object (`issues`, `workflow_runs`), so a machine with no gh, or an MCP server over the API, mirrors the same passages
